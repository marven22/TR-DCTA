# Dataset and environment setup

No benchmark data are redistributed by this repository.

## MetaWorld

- Official repository: https://github.com/Farama-Foundation/Metaworld
- Documentation: https://metaworld.farama.org/

Install MetaWorld and its compatible MuJoCo stack in an isolated environment.
Record the exact upstream commit in the artifact deposit. The final code-only
TR-DCTA evaluation can operate on frozen ledgers without importing MuJoCo;
end-to-end policy regeneration cannot.

## MiniGrid / BabyAI

- Official MiniGrid repository: https://github.com/Farama-Foundation/Minigrid
- BabyAI environment documentation:
  https://minigrid.farama.org/environments/babyai/

The held-out UnlockPickup experiment uses seeds 60 through 299. Seeds, source
priors, cascade variants, missing-provenance conditions, replay budgets, and
bootstrap seeds are specified in
`configs/babyai_unlockpickup_terminal_recovery_heldout_freeze_v1.json`.

## LIBERO

- Official repository: https://github.com/Lifelong-Robot-Learning/LIBERO
- Documentation:
  https://lifelong-robot-learning.github.io/LIBERO/html/getting_started/overview.html

LIBERO was used for the MemoRepair, MemAudit, active-search, and earlier DCTA
compatibility studies. These are preserved as secondary comparisons and are not
the primary MetaWorld/BabyAI TR-DCTA terminal-recovery claim.

## DDXPlus

- Official repository: https://github.com/mila-iqia/ddxplus
- English release:
  https://figshare.com/articles/dataset/DDXPlus_Dataset_English_/22687585
- Distributed under a CC-BY licence. Record the downloaded version and DOI in
  `configs/ddxplus_screen_freeze_v1.json` before any release run, and comply
  with the current upstream terms.

Place `release_evidences.json`, `release_conditions.json`, and the patient
split archives under `data/ddxplus/`, which is gitignored. The screen reads the
distributed `.zip` directly, so no extraction step is required and no dataset
bytes enter this repository.

DDXPlus supplies static records rather than a simulator, so `src/mcx/ddxplus.py`
defines the executable unit: a diagnostic procedure anchored on one pathology,
whose emitted diagnosis is compared with the record's `PATHOLOGY` field. Replay
labels are therefore ground truth from execution and no language model is
consulted. Build the eligibility ledger with:

```bash
python scripts/run_prob_dcta_ddxplus_screen.py \
  --config configs/ddxplus_screen_freeze_v1.json \
  --output results/ddxplus_screen_v1.json
```

`mcx.ddxplus.validate_sources` fails loudly when a release's JSON shape differs
from the adapter's reading. Run the screen once after downloading and confirm
it reports the expected condition and evidence counts before generating
archives.

DDXPlus is synthetically generated by a rule-based simulator. It supports no
clinical claim, and any result on it must be reported as an audit-method
transfer evaluation over medical decision text.

## Models

The semantic retrieval reconstruction uses the Hugging Face model and immutable
revision recorded in the MetaWorld configs. Model weights are downloaded from
the upstream host and are not stored here. Earlier MemoryArena generation can
optionally use the pinned Qwen checkpoint specified by the corresponding
configuration.
