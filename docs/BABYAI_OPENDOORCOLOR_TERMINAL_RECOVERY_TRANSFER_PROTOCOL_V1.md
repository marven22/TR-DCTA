# BabyAI OpenDoorColor terminal-recovery transfer protocol v1

## Status and purpose

This is a locked retrospective transfer of TR-DCTA, frozen after its
UnlockPickup development result, to the already-completed 240-context
OpenDoorColor evaluation. The OpenDoorColor outcomes have been examined before;
this study is therefore transfer evidence, not a new confirmatory held-out test.

## Frozen population and evidence

Reuse seeds 60--299, their 18-memory archives, executable corruption labels,
source priors, opaque identifiers, complete/33%-missing/67%-missing provenance
views, random trajectories, and replay budgets 2, 4, and 8 from the verified
OpenDoorColor report. No BabyAI execution, archive generation, label change,
mask change, posterior refit, or TR-DCTA tuning is allowed.

Every archive has one harmful three-memory family. Quarantine capacity is three
and recovery requires all three harmful memories to be removed.

## Methods and fairness

Run the frozen TR-DCTA implementation without modification. Preserve all
existing baseline replay policies: SC-DCTA, probabilistic DCTA, hard-source
DCTA, ENS, source information gain, static risk, 50 random replicates, and the
known-source DCTA ceiling. Add a privileged full-information hindsight ceiling.

Every deployable method receives the same terminal quarantine optimizer:
maximize posterior probability of full recovery, then expected captured harm.
The full-information hindsight ceiling alone receives the true affected set.
Baseline replay trajectories must exactly match the pinned source report.

## Outcomes

Primary reporting uses the two partial-provenance conditions at budget four.
Report recovery, weighted quarantine recall, replay-discovery recall, clean
removals, and runtime. Also report the complete provenance reference and budget
2/4/8 robustness curves.

Ten thousand paired archive bootstrap draws provide descriptive 95% intervals
for TR-DCTA minus SC-DCTA, probabilistic DCTA, hard-source DCTA, ENS, and random
on recovery and weighted quarantine recall. Because this benchmark was already
observed, these intervals are not labeled preregistered confirmatory tests.
